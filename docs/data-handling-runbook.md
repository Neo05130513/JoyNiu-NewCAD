# 数据保留与删除申请操作说明

本版本实现的是客户申请、人工处理与回执留存。没有自动物理删除功能，本说明也不授权批量删除生产数据。

## 客户入口

“支持与工单”→“申请删除数据”。客户选择原图及预览、模型与导出、项目/聊天/历史、账号资料、工单、备份等范围，说明具体项目、任务或时间范围，并明确知悉提交不会立即删除。可关联本人任务；附图授权仍默认否，申请不扩大访问权限。创建返回实际工单编号，重复提交同一请求不重复建单。

若需调整或撤回申请，客户追加说明；运营应先确认实际执行进度。客户关闭工单只结束当前沟通，不代表撤销已完成操作或完成物理删除。

## 运营处理

1. 在后台客服工作台查看“数据删除申请”，核对申请账号、身份核实方式及具体范围。仅按当前权限查看必要信息；工单本身不开放原图下载。
2. 若范围不清，填写“等待范围确认”回执，列明待确认问题；客户在原工单查看并补充。
3. 根据已发布政策列出各类数据的实际保留期限与原因。确认原图、衍生预览、STEP/GLB、任务记录、云工作区、历史版本、联系信息、工单、账本/审计和备份涉及哪些存储位置。
4. 如需物理删除，由有权限的人员对具体清单另行安排执行与核验。当前支持系统的消息、审计、幂等记录以及账本有不可改历史约束，不得绕过约束用随意 SQL 或删目录冒充可审计删除。共享附件、关联任务、历史证据和备份须逐项核对，不能按文件名猜测归属。
5. 在“登记人工数据处理回执”中选择实际结果：等待确认、处理中、申请范围已处理、部分处理、本次未执行删除。填写实际处理范围、仍保留的数据与原因、保留期限和备份安排、可核对的内部证据编号，并确认客户可见后保存。
6. 回执只记录结果，不执行文件/数据库删除，不发送邮件或短信。客户可查看历次回执；旧回执不可覆盖，后续更正追加新回执。版本冲突需刷新核对，重试同一请求不会重复记录。

“申请范围已处理”只能用于已确认范围且有证据的实际处理；备份未清理或部分记录仍应处理时选择“部分处理”，列明剩余安排。单纯修改工单为“已提供处理结论”不能替代回执。内部备注只供后台查看，不能当作已向客户告知。

## 保留政策待运营填写

| 数据类别 | 当前保存位置/形式 | 必须确定的规则 |
| --- | --- | --- |
| 原图、渲染与导出实体 | CAD 文件目录，任务引用 | [在线保存期限、到期动作、原图与衍生文件是否同时处理] |
| 项目、聊天、历史版本 | 云工作区、浏览器草稿与用户导出备份 | [云端保存期限、浏览器/用户副本说明、回收站保留期限] |
| 账号与联系资料 | 账号、客户档案 | [服务终止后的保留范围、删除或去标识处理安排] |
| 工单与授权记录 | 支持消息、回执、审计不可改历史 | [目的、必要保留字段、期限、届满后经审核的处理方法] |
| 收款、积分、售后、审计 | 事务账本与运营记录 | [适用保留依据、实际期限、不能立即处理的必要范围] |
| 备份副本 | 以实际备份清单与异地配置为准 | [轮替周期、最迟移除日期、隔离与恢复时重放已执行删除清单] |

这些期限没有预填数字；运营需确定实际可执行的期限后写入正式隐私说明。上线前确认负责人员、支持时间、处理记录保管方式。一次申请演练通过不代表自动保留策略已经运行。

## 已验证的程序边界

专项测试覆盖账户隔离、本人任务归属、范围与明确确认、客服权限、字段校验、回执版本冲突、幂等重试、客户可读回执、不可改历史和原始文件哈希不变。测试使用隔离临时数据库，不处理生产客户文件。
