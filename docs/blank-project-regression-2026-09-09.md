# 新建项目与空白文件回归

日期：2026-09-09。

## 原因与修复

- 新建项目、新建文件和恢复空快照原先会填入默认轴（外径 24、长 70）。现在空白文件以 `model: null` 保存，恢复时只读取文件名称、材料偏好，不创建几何。
- 中央预览显示建模引导，参数、特征、检查、工程图、装配与导出识别空白状态。只有用户主动创建基础轴或 AI 返回可用几何参数时才创建模型。
- 新建文件的默认选项改为“空白文件”；“复制当前文件的设计”继续保留明确的复制行为。已有项目和版本中的真实模型不做清理。
- 浏览器端到端测试发现，空白文件的文字请求缺少当前配方提示，暴露了 AI 严格响应 Schema 未允许返回零件身份的问题。已加入 `part_type` 和 `recipe_id`，明确轴的键槽字段与支架浅槽字段的区别。
- 无身份的旧响应仍可兼容；若混入多种配方的独有字段，前端保持当前类型或空白状态，不按配方顺序猜模型。仅闲聊、材料、单位或空参数不会生成模板。

## 验证

- 前端 `npm test`：79 项通过；后端 `test_ai_proxy.py`：90 项通过。
- `npm run build`、`git diff --check` 通过；保留原有大 bundle 提示。
- 在独立浏览器测试端口 5174 验证：新建项目、刷新、项目切换、新建空白文件均保持空白；旧项目模型正常恢复。
- 空白文件切换工程图显示建模引导；装配显示 0 个实例，没有虚构主件。
- 主动点击“创建基础轴”后，尺寸面板和中央模型正常出现。
- 真实远程 AI 复测：空白文件请求轴（外径 36、总长 100、通孔 10、键槽 6 × 3 × 40），返回正确轴类型及全部指定尺寸，中央显示有通孔和键槽的轴预览。

## 数据边界

修复前已自动保存的默认轴属于已有文件内容，不能可靠区分是否已被用户采用，因此不自动删除。此次行为变更适用于新建空白项目、空白文件，以及本就没有模型的快照。
