# 管理后台运营能力增强与验收 · 2026-09-10

本轮针对首版后台“页面简陋、能看的记录多、可完成的业务操作少”的问题，按客户运营、任务排障、财务查询和客服协作重新组织页面，并补齐真实持久化操作。

**本轮代码已完成本地接口、浏览器验收并部署到生产服务器。** 生产镜像、停写备份和线上检查范围见本文“生产发布记录”。本地业务写入验收与线上只读核查分别记录；前一版证据见 [首版管理员后台验收](admin-acceptance-2026-09-10.md)。

## 页面与操作组织

后台提供 16 个可见菜单，按权限显示，分成三个导航组：

- **运营工作台**：运营总览、客户管理、建模任务、客服工作台。
- **交易与积分**：充值订单、积分流水、任务结算、退款处理、发票处理、模型用量。
- **平台配置**：积分套餐、计费规则、账号与权限、服务条款、系统状态、操作审计。

旧 `/admin/billing` 保持兼容入口，不在菜单重复展示。顶部快捷搜索只提供当前账号有权进入的目标；侧栏可收起，小屏使用展开导航。客户档案按内容组织，财务各页只展示相关查询和操作，避免每页重复堆叠套餐与费率。

财务筛选由服务端执行，支持适用页面的客户编号 `ownerId`、记录搜索 `q`、状态／类型及起止日期。筛选后的总数与分页同口径；起止日期按 `Asia/Shanghai` 整日边界转换，不将 UTC 日期直接当作北京时间。混合时区的历史时间戳按实际时间排序。

工单深链接收 `q/status/assignedTo/priority/offset`，规范化后初始化真实筛选；直接打开链接、顶部搜索和浏览器回退会加载对应队列。客服页面内部的筛选仍是页面状态，不将其描述为全部筛选都已同步到地址栏。

## 数据与权限合同

### 客户档案及任务人工处理

- 客户 CRM、人工处理状态有独立版本号。提交时核对版本，过期版本产生冲突，不覆盖另一名同事的保存。
- 客户跟进和任务内部备注为追加记录，保存作者与时间，不提供修改或删除历史备注的入口。
- 写操作使用幂等编号，数据库变更与操作审计在同一事务完成。重复提交同一个请求不会多写一条记录。
- 客户维护与跟进授予管理员、运营及客服；财务和审计等有查询权限的岗位按权限只读。账号角色和计费规则仍受各自管理权限约束。
- 任务人工状态与 CAD 状态分开存储。真实运行中的停止仍沿用原停止流程，等待工作进程确认；本轮没有增加自动重试或代客户重新发起模型调用。

### 客服协作

新增 `support_assignment` 和 `support_internal_notes`，旧工单表结构保持兼容：没有分派记录的历史工单显示未分配、普通优先级。

- 负责人候选仅包含启用且具有 `support:manage` 或全权权限的账号。提交时服务端再次核验，不只依赖下拉选项。
- 被停用、移除客服权限的历史负责人会标为不可继续分派，需要管理员重新安排。
- 分派与优先级修改复用 `revision/idempotencyKey/reason`；内部备注使用 `body/revision/idempotencyKey`。
- 内部备注单独提供管理员接口，客户详情、列表、消息和重复请求回执都不返回内部备注内容、数量或内部人员分派。内部备注不会增加客户消息数，也不会将客户工单改成等待客户回复。
- 工单管理员权限在每次读取和写入时检查；撤权后不可继续读取备注。
- 常用回复只追加到当前草稿，保留原有草稿；需要操作人明确点击“保存并回复客户”。本轮验收只填入草稿，未提交客户回复。

主要新增及增强接口：

```text
GET   /api/v1/support/admin/assignees
GET   /api/v1/support/admin/tickets
      ?q=&assignedTo=me|unassigned|用户ID&priority=low|normal|high|urgent
      &status=pending|原有状态&limit=&offset=
PATCH /api/v1/support/admin/tickets/{id}
GET   /api/v1/support/admin/tickets/{id}/notes?limit=&offset=
POST  /api/v1/support/admin/tickets/{id}/notes
```

管理员工单 DTO 增加 `assignedTo/assignee/priority/internalNoteCount`；列表额外返回 `views: {pending,mine,unassigned}`，视图数量按全队列对应条件计算。

### 统计与导出口径

- 工单待处理仅为 `open/in_progress`；`waiting_customer`、`resolved` 和 `closed` 不计入待处理积压。
- 任务 `ready` 才计为完成，`review_required` 和 `needs_input` 分别展示，不混称生成成功率。
- 历史没有调用日志的 Token、成本仍标明未知；供应商请求次数、明确记录的重试次数和计量调用数分开。
- 收款数据仅来自已有确认记录；缺完整费用和汇率依据时不生成利润或毛利率。
- 当前页 CSV 明确标注范围，处理公式起始字符等表格注入风险。管理页不输出完整支付报文、签名、Token 或客户图纸。
- 未增加没有采集依据的活跃度、留存率、下载量、CPU 历史曲线或“备份成功”指标。

## 本地真实浏览器与接口验收

在隔离本地验收数据上执行，桌面视口为 **1440 × 1000**：

1. 修改客户 CRM 后保存，再通过真实 HTTP 读取，核对保存值；追加客户跟进并确认作者、时间和内容。
2. 修改任务人工处理状态、优先级并追加内部备注；复查 CAD 实际状态保持原值，未触发建模。
3. 逐个打开七个独立财务页面，确认真实 API 查询正常；执行订单无匹配条件搜索，显示相应空结果，没有沿用未筛选数据。
4. 客服实际分派负责人、设置优先级并保存，添加内部备注；确认后端持久化且客户消息数不变。
5. 选择常用回复后内容只进入草稿，未点击发送；客户消息数保持不变。
6. **390 px** 小屏检查未出现页面横向溢出；发现移动导航遮挡后已修复并复查通过。

验收后恢复原 QA 客户资料、任务人工安排及工单分派。客户跟进、任务／工单内部备注属于追加审计记录，保留在本地验收数据中，不通过删除历史记录伪装为从未执行。

本轮没有写入线上客户业务记录，没有生成 AI 任务，没有执行付款、退款、扣积分或站外消息。这些交互结果来自本地真实界面与接口，不能表述为所有线上页面已经逐个验收。

## 保留的商业和运行边界

- 用户明确排除的三项仍不加入：建模前费用预估／最高消费提示、任务积分冻结、达到客户预算上限后暂停确认。
- 实际购买、扣积分和退款执行保持关闭；未设置假价格、假订单或假营业额。
- 现有模型供应商、模型、推理强度、Codex 登录和网络出口保持原配置。本轮没有触发模型调用来验证后台。
- 外部持续监控、通知、自动异地备份及正式商业渠道等事项仍按实际配置和专项验收结果区分；后台显示状态不代表这些外部服务已经开通。
