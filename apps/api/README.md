# JoyNiu NewCAD geometry API

apps/api is the service boundary for the drawing-to-3D acceptance flow. It
accepts one drawing upload, returns an auditable parameter interpretation, runs
bracket checks, and emits STEP and GLB artifacts.

## Run locally

~~~bash
cd apps/api
python3 -m venv .venv
. .venv/bin/activate
pip install -e '.[dev,geometry,ocr]'
uvicorn app.main:app --reload --port 8010
~~~

The complete local acceptance install includes FastAPI, CadQuery/OCCT and the
optional OCR adapter. CadQuery wheels are platform/Python-version dependent;
when they cannot be installed the API remains usable, but marks every output
as a review-only fallback.

~~~bash
pip install -e '.[geometry]'
~~~

Optional OCR support:

~~~bash
pip install -e '.[ocr]'
# macOS: brew install tesseract
~~~

OpenAPI is available at http://localhost:8010/docs and
http://localhost:8010/redoc (the JSON schema is at `/openapi.json`).

## Health and engine state

~~~bash
curl -s http://localhost:8010/api/health | jq
~~~

The status is "ok" when CadQuery/OCCT is importable and "degraded" otherwise.
The response always exposes geometry.engine, geometry.error, and capabilities.
In degraded mode GLB is generated by a deterministic mesh builder and STEP is
an AP242 tessellated preview. Both artifacts carry productionReady=false; no
fallback file is presented as a production B-Rep.

Set JOYNIU_DISABLE_CADQUERY=1 to test this path even on a machine with
CadQuery installed.

## Drawing workflow

### 1. Upload a sheet

~~~bash
curl -X POST http://localhost:8010/api/drawings/recognize \
  -F 'file=@bracket.png' \
  -F 'hints={"baseLength":100,"baseWidth":50}'
~~~

The response contains a stable id, source SHA-256, image dimensions (when
available), parameters, OCR text, an evidence record for every inferred field,
warnings, and a complete validation report. The supplied acceptance sheet is
calibrated to:

| Field | Value (mm) |
| --- | ---: |
| baseLength x baseWidth x baseThickness | 100 x 50 x 10 |
| upperLength x upperWidth x upperHeight | 70 x 30 x 30 |
| totalHeight | 40 |
| notchOpening / notchRadius | 40 / 15 |
| bossDiameter / bossCenterDistance | 20 / 70 |

OCR is attempted when Pillow + Tesseract are installed. If they are not, the
response explicitly says that a calibrated/reviewable profile was used. A
vision service can submit its own result through POST /api/drawings/results
using the same parameter schema; that compatibility route always remains
`needs_review` until an authenticated reviewer confirms it.

For the platform workflow, use the authenticated evidence endpoints:

~~~bash
# designer: analyze the exact image (base64 shown abbreviated here)
curl -X POST http://localhost:8010/api/v1/ocr/analyze \
  -H "Authorization: Bearer $DESIGNER_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"filename":"bracket.jpg","imageBase64":"..."}'

# reviewer: confirm the returned recognitionId
curl -X POST http://localhost:8010/api/v1/ocr/<recognitionId>/confirm \
  -H "Authorization: Bearer $REVIEWER_TOKEN" \
  -H 'content-type: application/json' -d '{}'
~~~

### 2. Validate dimensions

~~~bash
curl -X POST http://localhost:8010/api/brackets/validate \
  -H 'content-type: application/json' \
  -d '{"baseLength":100,"baseWidth":50,"baseThickness":10,
       "upperLength":70,"upperWidth":30,"upperHeight":30,"totalHeight":40,
       "notchOpening":40,"notchRadius":15,"bossDiameter":20,
       "bossCenterDistance":70}'
~~~

Validation is non-throwing and returns all rules. valid=false means an
error-level rule failed; warnings do not block a preview. The U-slot checks
include notch.arc_center (Z=totalHeight) and notch.bottom
(Z=totalHeight-notchRadius, therefore Z=25 for the acceptance sheet).

### 3. Generate and download

~~~bash
curl -X POST http://localhost:8010/api/brackets/generate \
  -H 'content-type: application/json' \
  -d '{"parameters":{"baseLength":100,"baseWidth":50,"baseThickness":10,
       "upperLength":70,"upperWidth":30,"upperHeight":30,"totalHeight":40,
       "notchOpening":40,"notchRadius":15,"bossDiameter":20,
       "bossCenterDistance":70},"formats":["step","glb"]}'
~~~

The JSON response includes requestId, the validation report, and artifact
descriptors (id, format, byte size, SHA-256, engine, and downloadUrl).
Download either descriptor URL, or use the convenience endpoint:

~~~bash
curl -X POST http://localhost:8010/api/brackets/export/step \
  -H 'content-type: application/json' \
  -d @bracket-parameters.json -o bracket.step
~~~

Invalid dimensions return HTTP 422 with the full validation report and no
artifact. requireCadQuery=true returns HTTP 503 when OCCT is unavailable,
which lets a production caller enforce a B-Rep-only release gate.

## Coordinate recipe

The canonical model uses millimetres and a centred XY origin:

* Base plate: 100 x 50 x 10, from Z=0 to Z=10.
* Upper body: 70 x 30 x 30, centred on the base, from Z=10 to Z=40.
* U-slot: through the upper body's Y width; arc centre lies on Z=40,
  radius 15, bottom Z=25, with a 40 mm top opening.
* Two vertical diameter-20 bosses at (X,Y)=(-35,0) and (35,0), from Z=10
  to Z=40.

CadQuery builds a fused solid and cuts the slot with an OCCT horizontal
cylinder. The fallback GLB uses a segmented analytic arc and the fallback
STEP uses an AP242 triangulated face set, so the same dimensions remain
inspectable in either environment.

## Persistence and production boundary

With `JOYNIU_DB` set to a filesystem path, accounts, PDM projects/documents and
CAM plans/simulations/approvals/NC snapshots survive an API restart. The direct
geometry artifact cache and the OCR recognition hand-off map are intentionally
process-local; the authenticated `drawing-to-model` workflow stores the source
bytes, complete OCR evidence/recipe, validation metrics and generated artifacts
as immutable PDM versions before returning. Keep the returned SHA-256 and
validation report with every released file for traceability.

The built-in Tesseract adapter is a real local OCR provider, while the supplied
acceptance sheet uses a SHA-verified calibration fixture for deterministic CI.
Unknown drawings stay in `needs_review` until a reviewer maps their dimensions
and topology to a supported recipe. CAM's deterministic pre-check and generic
postprocessor are workflow gates/design drafts, not machine-specific material
removal simulation or certified production NC.
